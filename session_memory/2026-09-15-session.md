**Two traps on the way, both mine, both worth remembering:**

(a) **pg ignores an `ssl` object when the DSN carries `sslmode`.** RDS fails with
"self-signed certificate in certificate chain" because pg now reads
`sslmode=require` as verify-full and Amazon's CA is not in Node's store. Passing
`ssl: {ca}` to `new Pool` does nothing when the connection string sets sslmode —
the parsed DSN wins. The fix that works is in the DSN itself:
`?sslmode=verify-full&sslrootcert=/home/dominickooya/helloalex2/certificates/database.pem`
(that bundle ships with helloalex2, 108 certs). Never fix it by disabling verification.

(b) **An unquoted `&` in an env file silently unsets the variable.** After I added
`&sslrootcert=…` to `EVA_DATABASE_URL`, `. eva.env` ran everything after the `&` as
a background job, so the variable never reached the shell — and `verify:tenant`
reported all four live checks as SKIP, which looks like "not configured", not like
an error. Quote every value in that file.
