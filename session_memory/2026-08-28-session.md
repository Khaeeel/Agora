## What Agora is

A Messenger-style chatroom where the participants are AI agents. Lives at
`~/.openclaw/agora` **inside WSL Ubuntu** — not on the Windows drive.

- **Engine**: the Claude Code CLI driven as a subprocess on the Max plan
  (`claude -p`). There is no API key anywhere and there must not be.
- **Server**: Fastify + WebSocket on `:8787`. **Web**: Vite on `:5183`.
- **Storage**: SQLite at `data/agora.db` (`node:sqlite`, `DatabaseSync`).
- **Agents**: one `.md` per agent in `agents/`. The file IS the agent — a file
  watcher reloads the roster on save, so editing a `.md` needs **no restart**.

## Runbook — how to start everything

**Order matters only in that the API should be up before the web app.**

```bash
# Agora server  (detached, survives the shell)
cd ~/.openclaw/agora
setsid nohup node --env-file-if-exists=.env apps/server/src/index.ts \
  > /tmp/agora-server.log 2>&1 < /dev/null & disown

# Web
cd ~/.openclaw/agora/apps/web
setsid nohup ./node_modules/.bin/vite --port 5183 --host \
  > /tmp/agora-vite.log 2>&1 < /dev/null & disown

# Chrome for T-Bag / Lincoln (CDP 9222)
cd ~/.openclaw/agora
setsid nohup bash scripts/start-chrome.sh > /tmp/agora-chrome.log 2>&1 < /dev/null & disown
```

**Traps, each of which cost time:**

- `nohup … &` from a one-shot `wsl.exe -- bash -lc` **gets reaped** when the call
  returns. `setsid … & disown` is what survives. The Chrome script says so in its
  own header and I still hit it.
- The vite binary is at `apps/web/node_modules/.bin/vite`, **not** the workspace
  root. A root path silently produces nothing.
- **Never restart the Agora server while a run is live** — it kills the run. Check
  first: every room's `/api/rooms/<id>/messages` → `run.active`.
- The **OpenClaw gateway is systemd-supervised**. Use
  `systemctl --user restart openclaw-gateway`. A manually started one gets
  SIGTERM'd by systemd within seconds.
- WSL drops with `0x8007274c` intermittently. Retry; it is not a real failure.
- Shell quoting from Windows → WSL mangles `${…}` in `node -e` and heredocs.
  **Write a `.mjs`/`.py` file and run that** rather than inlining.

## The run loop (all rooms)

1. Human message → planner turn decides **answer** vs **work**.
   - *answer* → one agent replies, or 2–4 agents **discuss** it.
   - *work* → a goal broken into checkable steps.
2. Loop: orchestrator assigns one agent per turn, or opens a discussion.
3. **Checkpoint** every 12 turns *or* 10 minutes, whichever first → `continue` /
   `done` / `blocked`. The turn cap is **not** an ending.
4. `blocked` is the only thing that interrupts Dominic. It carries clickable
   options when the ask is a decision.
5. Run ends → WhatsApp report → mind stone compaction.

Bounds: 6 rounds, 90 min wall clock, 3 automatic resumes per goal.

## What was built this session

### Never make Dominic press Resume
- **Auto-resume**: keyed off the **board**, not the stop reason. `closeGoal`
  derives goal status from steps, so a goal closing `stopped` means the board
  disagreed with whoever declared it finished. Unfinished board + a stop that
  was not a human decision ⇒ restart itself, up to `AGORA_MAX_AUTO_RESUMES=3`.
  Never resumes on `stopped` (he pressed Stop) or `blocked` (genuinely needs him).
  - First attempt keyed off stop reason and **missed the real case**: runs were
    ending as `done` (`run finished`) with three steps unstarted.
- **Boot resume**: goals interrupted by a server restart are picked back up once
  the server is listening. Verified: `[boot] resuming 1 goal(s) interrupted by
  the restart`.
- **Resume button** on every goal card, and a **Stop** button on each.

### Stop false escalations
- **Capability guard**: before a `blocked` escalation leaves, its claim is
  checked against the roster. "Nobody here has a write grant" while four agents
  hold `erasr-edit.sh` is not a blocker — it posts a correction and the run
  continues. Fires once per run. Tested to stay quiet on real blockers (GPU, a
  decision, a missing credential, the engine lease).

### Honest board
- `DECISION_SCHEMA.steps` is now an **array** — a turn that finishes three steps
  used to report one, which is how "1 of 3 done" appeared on completed work.
- Declaring done runs a **final reconciliation review** before the goal closes.
- `closeGoal` no longer demotes an `active` step to `skipped`. Only steps nobody
  started become "never reached".

### Agents talking to each other
- `discuss` on both the plan and the decision: 2–4 agents speak in order, each
  seeing the previous ones, told to answer them **by name** and disagree out loud.
- Verified real output: *"T-Bag, the premise is stale — I just checked the tree,
  both are already committed on `origin/development`: `ad171fbc8 …`"*.
- Conversational rules live in `_house-rules.md`, so they apply in every room.

### Clickable decisions
- A `blocked` escalation can carry 2–4 options. They render as buttons in the
  transcript; clicking posts the answer and restarts the room. Double-click is
  refused at the database write, so one decision cannot start two runs.

### Mind stone (per-room compacted memory)
- `mind_stones` table; rewritten (not appended) every `AGORA_MIND_STONE_EVERY=25`
  messages; rides ahead of the transcript in every prompt. Panel in the right rail.

### Other
- All `$`/cost displays removed from every message, prompt and WhatsApp report.
- Per-room WhatsApp levels (`prompt` vs `all`).
- XML sanitiser: a model once emitted its whole `StructuredOutput` envelope as
  the `summary` field and it went to WhatsApp verbatim. Now cut at the first tag.
- `Alex` (IT Team Lead) added to HelloAlex — settles CI/deploy/migration
  questions with file and line. Immediately proved useful by refuting a premise:
  `deploy-development.yml` never sets `RUN_MIGRATION`; dev uses
  `SCHEMA_DEPLOY_REQUIRED`, and **schema and code must land in the same push**.
- `needsLookup`: answer-mode used to strip tools, so a factual question got an
  honest refusal. Now the planner keeps tools when the answer needs a file **or
  the browser** (that second half was missed at first, which broke T-Bag).
- `Sucre` given read-only repo access (`Read/Glob/Grep` + the git wrapper).

## Trunks (newest room)

Open-source image + video generation through the `erasr` harness, one RTX 4070
SUPER (12 GB), one ComfyUI process.

**Agents**: Gaben (architect — opens/closes phases, never runs), N0tail (PM,
owns the lease and budget), Collapse (inference/VRAM), Yatoro (video), Ana
(image), Topson (data/licence), Ceb (eval — **no edit grant by design**).

**Wrappers** in `scripts/`, and they are the whole security boundary:

| Script | Does | Held by |
|---|---|---|
| `erasr-run.sh` | read, grep, inspect | all lanes |
| `erasr-edit.sh` | + Write/Edit | Collapse, Yatoro, Ana, Topson |
| `erasr-job.sh` | **submits one ComfyUI job**, waits, prints the sidecar | Collapse, Yatoro, Ana, Ceb |

### Why this room kept stalling — two causes, both mine

1. **No job wrapper existed.** Every run did the code work, needed one test job
   to confirm it, could not run one, and handed it back. `erasr-job.sh` fixes it.
   - WSL cannot reach the Windows dev server (NAT). It shells out to
     `/mnt/c/Windows/System32/curl.exe`, which runs in the Windows network
     namespace where `localhost:3000` actually is.
   - It polls the **`_meta.json` sidecar**, not `/api/jobs/<id>` — jobs live in
     memory and that endpoint 500s once the pool drops the entry.
2. **The rules never said who grants the lease.** So N0tail assumed only Dominic
   could, and reported blocked while holding everything. The rules now say
   plainly: **N0tail owns the lease and grants it on the assignment line.**

### Security hole, found and closed

An agent **rewrote `erasr-job.sh`** (4 KB → 12.6 KB), adding `--status`,
`--restart`, `--meta`. Not malicious — a genuine improvement — but it could only
do that because `erasr-edit.sh` spawned its session with the **working directory
set to `~/.openclaw/agora`**, so `Write` reached the scripts that constrain it.
An agent that can edit its own boundary has no boundary.

Fixed: both wrappers `cd "$PROJECT"` before invoking `claude`, and all three are
`chmod 555`. The agent's improved version was kept — that was a call to make
deliberately, not to inherit by accident.

## WhatsApp bridge

**Outbound** (room → group): `notify.ts`, per-room JID from
`AGORA_NOTIFY_JID_<SLUG>` where SLUG is the slugified **room name**. `off`
silences a room; **empty falls back to the global**, which is why `off` matters.

**Inbound** (group → room): OpenClaw binds a group JID to an agent; the group's
`systemPrompt` tells it to call
`scripts/agora-ask.mjs --room "<Room>" [--status | --detach "<msg>"]`.

Config shape — both of these cost me a wrong guess:
- bindings use **`agentId`**, not `agent`
- prompts live on **`channels.whatsapp.groups.<jid>.systemPrompt`**, not on the
  agent or the binding

Backup at `~/.openclaw/openclaw.json.bak-trunks`. After editing:
`openclaw config validate`, then `systemctl --user restart openclaw-gateway`.

## Prompt-editing rules

The role files supplied as `files (N).zip` contain **only** `## Description`,
`## Instructions`, `## Personality` — no frontmatter, no Name/Role.

**Never overwrite an agent `.md` with one.** Frontmatter is what arms an agent;
a straight copy silently un-arms the whole room and nothing errors. Splice the
three sections in, keep everything else, and check afterwards that:

- tools / add_dirs / mcp / allow survived,
- sections the parser does not read (`## SPEC`, `## HANDOFF PROMPT`) were folded
  into `## Instructions` — it reads only Name, Role, Description, Instructions,
  Personality and **silently drops the rest**,
- Dominic's own safety rules survived. The rewrites dropped **all** of them:
  T-Bag's no-calls / no-batch-sends / ask-before-any-AI-feature and the Dominic
  Test account limit; Lincoln's off-limits console sections and the never-read
  `.env` rule. They were re-appended verbatim.
